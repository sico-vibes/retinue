# Reviewing changes and pull requests

After an employee changes files, you can review the changes before you keep them. Review shows what changed, file by file, so you can check the work the same way you would check a colleague's.

![The changes view for a conversation](/docs/docs-review-dark.webp)

## Steps: review a change

1. Open the changes view for the conversation.
2. Choose the scope you want to see: uncommitted work, the last turn, the whole branch, or the last commit.
3. Open a file to read its changes.
4. Ask the employee in the conversation to fix anything you do not like.

## Pull requests

If your project is on GitHub, ask the employee in the conversation to open a pull request for the work. It can give you the link to review on GitHub. Check the pull request before you merge it, as you would for any change.

## Good to know

- Review shows the employee's changes as they are. Ask the employee to fix anything before you accept the work.
- For the same task done by several employees, see [Comparing employees on one task](/docs/comparing-employees-on-one-task/).
