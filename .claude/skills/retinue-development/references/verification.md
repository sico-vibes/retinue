## Smart App Control on the owner's PC (14 November 2026)

- `cargo check`/`cargo test` in the main checkout's own `target` can stop at a build script with `An Application Control policy has blocked this file. (os error 4551)`. Use a lane worktree's target whose build scripts already ran: `CARGO_TARGET_DIR='C:\Users\Sico Vibes\Desktop\DevCN\Retinue-retinue\<worktree>\target'`, with `TEMP`/`TMP` at `C:\tmp`.
- A freshly linked **test binary** is often blocked the same way. Build it with `--no-run`, copy `deps\retinued-<hash>.exe` to `C:\tmp\`, and run the copy with the test filter; the copy runs (17 November 2026, all 7 connector tests). See `lessons.md`, "Smart App Control blocks a fresh proc-macro dll".
- **The same block on a proc-macro DLL reads as `error[E0463]: can't find crate for `async_trait``** (also seen for `tokio_macros`, `futures_macro`, `tracing_attributes`). Cargo passed the `.dll`; rustc could not load it. Delete the crate's artifacts (`cargo clean -p async-trait`) and rebuild, sometimes twice.
- **A loop is the practical answer**: run the gate, read the blocked crate/script names out of the output, `Remove-Item -Recurse -Force <target>\debug\build\<crate>-*` (or `cargo clean -p <crate>`), and rerun; four to eight rounds is normal on a cold target. A blocked *test binary* is the same: delete the `.exe` and relink.
- **19 November 2026: the path comes *before* the sentence.** A blocked DLL reads `error: \\?\…\deps\<crate>-<hash>.dll: LoadLibraryExW failed: An Application Control policy has blocked this file. (os error 4551)`, so a script that scrapes a crate name out of the phrase after it finds nothing and gives up. Match `deps\\<crate>-[0-9a-f]{8,}\.(dll|exe)` (and keep the `E0463 can't find crate for \`x\`` pattern beside it). One `cargo check -p retinue-daemon --all-targets` on this date needed `tokio-macros`, `tracing`, `tracing-attributes`, `futures-util`, `futures-macro`, `url` and finally `yoke-derive`, cleaned one per round; the next round passed. Check the library alone first — it needs fewer relinks than `--all-targets` — and the script driven loop is faster than doing it by hand.
- **`cargo check -p retinue-daemon --all-targets` can abort with `STATUS_STACK_BUFFER_OVERRUN` (0xc0000409)** while compiling the daemon's test binary: set `$env:RUST_MIN_STACK='33554432'` for checks too, not only for `cargo test`.
- **22 November 2026: prove test code without linking a binary.** When the policy refuses every freshly linked `.exe`, `cargo check -p retinue-daemon --tests` still typechecks the test target (`import_tests.rs` and friends) in about 3 minutes on a warm target and links nothing, and `cargo clippy -p retinue-daemon -p retinue-storage --all-targets -- -D warnings` compiles the test target and stops before linking too — so lint failures in test code are found even though no test can run. Report the run as "typechecked, not executed (Smart App Control)" and let CI run the tests. Also: cargo writes its progress lines to stderr, so `cargo ... | Select-Object` leaves `$LASTEXITCODE` at 1 even on success. Confirm with `cargo ... 2>$null; "exit=$LASTEXITCODE"` (prints 0) rather than reading the pipeline's exit code; a `Finished` line with no `error` is success.
- **Never delete artifacts in another lane's or the main checkout's target** (22 November 2026): the Director builds in the main checkout, so removing a blocked script or DLL there breaks that build. Use your own worktree's `target` only, and when the same scripts are blocked on every attempt, stop looping and hand the test run to CI.
- **17 November 2026: newly linked executables are blocked too.** On this PC the policy now refuses any freshly built `.exe` (a build script, a test binary) when it is executed, so a lane can compile (`cargo check`, `cargo test --no-run`) but never *run* a test binary it just linked. Only executables built before the policy was applied still run, and a relink **overwrites** the same `deps\retinued-<hash>.exe`, so a binary that ran tests ten minutes ago is blocked after the next build. The only target whose third-party build scripts run is the main checkout's warm one; a private `CARGO_TARGET_DIR` copied from it (`debug` only, fingerprints use paths relative to the target) compiles a crate without re-running them, but cargo re-links the test binary after any edit and the policy then blocks it. Report tests as "typechecked" or "written, not executed" rather than as passing. A shared target also lets one lane run another lane's stale test binary; check `cargo test -p <crate> -- --list` for the test's own name. **It is not absolute (17 November 2026, OAuth lane):** of five relinks, two were allowed. Deleting the `.exe` and relinking (8–12 minutes here) is worth one or two attempts; copying or renaming a blocked file never helps, because the decision is per content.
- **Run a copied daemon test binary from `crates/retinue-daemon`, with `TEMP`/`TMP` at `C:\tmp`.** Otherwise two families fail for no code reason: `fix39_p12_tests::every_log_call_site_is_a_fixed_message` (its roots are `../../crates/…` relative to the working directory) and the `repository` / `session.repository` tests (git answers with the 8.3 short form of `C:\Users\Sico Vibes\AppData\Local\Temp`, `SICOVI~1`, which is not the long path the test expects). Both pass alone with the right environment (17 November 2026).
- **21 November 2026: copy same-named artifacts from an older sibling target.** A blocked daemon build script (`target\debug\build\retinue-daemon-b515ed9ee5609579\build-script-build.exe`) was restored by copying that exact file from `follow-up-prompt-suggestions-the-daemon`; blocked `_derive`/`_impl`/`_macros` DLLs (rustc's `can't find crate` gives no path, the `LoadLibraryExW failed` line does) were fixed by copying every same-named macro DLL from the older `slim-tool-call-storage-backend-task-from` target (`Get-ChildItem …deps\*.dll | ? Name -match '(_derive|_impl|_macros|macros)-[0-9a-f]{8,}\.dll$'`), after which `cargo test -p retinue-storage --lib` passed 190/190. A freshly linked daemon test binary was refused once and then ran in place with no copy, after one `cargo test --profile dev -p retinue-daemon --bin retinued --no-run` relink: the "newly linked executables are blocked" rule is a tendency, not a constant. Run it from `crates/retinue-daemon`.
- **A lane's own target is the only reliable place to run its tests (17 November 2026, confirmed).** In the shared target, `--no-run`'s reported executable was another worktree's build (its `--list` had none of the lane's tests, and none of its `include_str!` bytes). `robocopy <shared>\target\debug <lane>\target\debug /E /MT:16` (55 GB) then building with `CARGO_TARGET_DIR=<lane>\target` gave a binary that was provably the lane's, and 8 + 13 + 70 + 87 tests ran. Expect `E0463 can't find crate for …` once: delete the named crates' `.fingerprint` and `deps` entries and rebuild, and do the same for a proc-macro DLL (`deps\tracing_attributes*`), which SAC blocks even though the copied source was allowed. Recipe and symptoms: `lessons.md`, same date.
- Test only the changed crates (`-p retinue-daemon -p retinue-storage ...`): `--workspace` pulls a crate whose new build script is blocked. Test programs that start helper binaries (the Codex adapter's `app_server` tests with `fake_codex_server`, agent core's unit tests) are blocked too; CI runs them. Say so in the report.
- `remoteBuild.test.ts` runs `npm run build:remote` itself. Under Vitest `NODE_ENV` is `test`, and the build inherited it, measuring 1.72 MB against the real 1.45 MB, so the test failed on `main` and CI skipped every later step (daemon tests, clippy, builds) on every push. Fixed 14 November 2026 by building with `NODE_ENV=production`. When CI fails at the unit tests, check whether the Rust steps ran at all.
- `npm run docs:check` skips `apps/site/content/` (website pages link by site routes).

## Linux (17 November 2026)

- Nothing on this PC can prove a Linux build. `rustup target add x86_64-unknown-linux-gnu` installs the standard library, but `cargo check --target x86_64-unknown-linux-gnu` then stops at `libc`'s and `proc-macro2`'s build scripts with os error 4551 (every build script for a new target is a fresh `.exe`), and `rusqlite` (`bundled`) and `rustls` (`ring`) would need a cross C toolchain anyway. **The CI `linux` job is the proof**, and a lane reports "typechecked on Windows, not built on Linux".
- **18 November 2026: the `linux` job runs the daemon's whole suite**, so a Windows-shaped test fails there first (13 did at `79d9ae1`; report `docs/reports/linux-ci-fixes.md`). Before adding a test, ask what each literal means on Linux; write both platform shapes with `if cfg!(windows)` so the Windows clippy run typechecks the Linux side too. `clippy -p retinue-daemon --all-targets -- -D warnings` sees `#[cfg(unix)]` code only in CI.
- A change that could break Linux is the one to look at twice: an ungated use of a Windows API, a file mode, a path separator, a binary name (`tailscale` not `tailscale.exe`, `retinue-hook` not `retinue-hook.exe`), and a `.exe` in a spawn argument. `crates/retinue-daemon/src/console.rs` and `paths.rs` are the two modules written for it.
- The headless flow on a host, in order: `retinued` (unit sets `RETINUE_HEADLESS=1`) → `retinued remote on --method tailscale` → `retinued pair` → approve on the host with `retinued pair confirm --tier chat`. `console.json` in the data folder is the console client's only credential, and it is not the capability.

From the repository root (or a worktree):

```powershell

# desktop crate: only from a short path (see below)
```

- **CI is split by path (2026-11-17, wave 3, idea 4).** Jobs: `hygiene` (the fast checks, always), `types`, `uiTests`, `build`, `daemonTests`, `clippy`, `docs`, `perf`, then one required `checks` job that fails unless every check the `scope` job selected passed. `scripts/ci-scope.mjs` is the table and `scripts/ci-scope.test.mjs` pins it (one real path per rule, unknown paths run everything, the workflow's jobs match the table). Reproduce a selection locally with `node scripts/ci-scope.mjs --paths <changed files>`; reproduce a full run with `--full`. A nightly run at 04:10 UTC runs everything. Workflows only run when pushed, so a lane proves what it can locally — the YAML parses, every rule names an existing folder, every script the workflows name exists — and says the rest is CI's to prove. To parse a workflow locally there is no YAML package in the tree: `npm install yaml@2 --no-save` in a scratch folder outside the repository and parse from there (done on 17 November 2026; both workflow files parsed and every job's `needs` resolved).
- **The release refuses a red commit and a stale version (2026-11-17).** `release.yml`'s `require-ci` job asks `gh api` for `ci.yml` runs on the commit and fails unless the newest concluded success. `scripts/release-windows.ps1` runs `scripts/update-round-trip.mjs` on the manifest it wrote (and against the published `channel-beta` version) and refuses an equal or older version. `scripts/update-round-trip.test.mjs` proves the round trip against `make-update-manifest.mjs`'s own writer; the reader's rules are `tauri-plugin-updater` 2.10.1's `RemoteRelease` (`~/.cargo/registry/src/*/tauri-plugin-updater-2.10.1/src/updater.rs`).
- `npm run check:architecture` is the boundary table (`scripts/check-architecture.mjs`): a crate's `retinue-*` dependencies, HTTP clients outside the daemon and speech, a new daemon module opening a network client, a `WebSocket` outside the transport seam, and production code importing `preview/`. Its exceptions are listed in `ALLOWLIST` with a reason, and an exception that no longer matches anything fails the check. A new crate needs a row.
- `npm run check:format` deliberately does not reformat anything (2026-11-16): it reads encoding, a BOM, a NUL byte, trailing whitespace and mixed line endings for code and config, and leaves Markdown alone (two trailing spaces are a hard break, and `docs/library/` is generated). Prettier is not adopted: the tree is hand-formatted, so a formatter means one enormous commit and a fight with the house style. `cargo fmt --check` is still not a gate.
- The git hooks are opt-in: `npm run hooks:install` writes `.git/hooks/pre-commit` (formatting from the index, then `gitleaks git --pre-commit --staged`) and `.git/hooks/pre-push` (architecture, formatting, script tests). The hook files live in `.git` because a tracked one arrives with CRLF and `sh` refuses it, and git keeps them in the clone's shared git directory, so one install covers every worktree (and `--remove` removes them everywhere). The pre-commit secret scan skips itself, with a printed note, when `gitleaks` is not installed; CI scans regardless.
- Every new check above must pass on the code as it is, with a fix or a reasoned allowlist entry, not with an exclusion nobody will revisit.
- `spawn_window_tests::no_spawn_that_can_show_a_console_window` (daemon tests, 21 November 2026) scans every `Command::new(` in `crates/*/src` and `apps/desktop/src-tauri/src` and fails unless the spawn goes through `prepare_command`/`hide_window` or writes `CREATE_NO_WINDOW`; its exception list carries one reason per entry (test helpers, Unix-only commands, the owner's editor, Explorer, the sign-in terminal) and an exact count per file. A new spawn is hidden, or added there on purpose.

- Run vitest from `apps/desktop` (`cd apps/desktop; npx vitest run <file>`); from the root, `--root apps/desktop` fails for tests that mount `App` ("Denied ID ...docs/releases"). `FIX37.updateBadge` fails on `main` at `30c7b3d` (expects beta.36), and `cargo clippy --workspace` fails inside `retinue-desktop` on Rust 1.94 in untouched code; use `--exclude retinue-desktop` for a clean clippy run. `cargo clippy -p retinue-desktop` itself (8 November 2026, beta.50) stops at one error, `power.rs:222` `clippy::never_loop`, plus 8 warnings in `speech.rs`, `pty.rs`, `lib.rs` — all untouched code, none in a new command.
- A fresh `CARGO_TARGET_DIR` makes `sherpa-onnx-sys`'s build script download 1.1 GB of prebuilt libs into `<target>\sherpa-onnx-prebuilt`; on 8 November 2026 that failed with HTTP 503 from GitHub. Don't copy the cache: point `SHERPA_ONNX_LIB_DIR` at an existing one (`<any other target>\sherpa-onnx-prebuilt\sherpa-onnx-v1.13.8-win-x64-static-MT-Release-lib\lib`).
- Run the Vitest suite on a quiet machine. When lanes or cargo builds run at the same time, mounted tests time out in large numbers (57 and 100 false failures were seen); re-run the failing files alone, or use `npx vitest run --maxWorkers=4`, before believing a failure. When other lanes are building, run `npm run test --workspace @retinue/desktop -- --maxWorkers=2 --testTimeout=30000` from the worktree root. The root `npm test -- ...` wrapper drops the Vitest flags in its nested npm call (21 November 2026). Keep the unfiltered log. An exit of 1 can accompany passing assertions when the worker reports `Timeout calling "onTaskUpdate"`; that timeout is in Vitest worker messaging, outside the individual test timeout.

The app plays a launch intro and fades the shell in; screenshots taken in the first seconds show a dimmed or empty window. Wait or check `getComputedStyle(document.querySelector('.app-shell')).opacity === '1'`. The real window is at least 1000 px wide; layout overlaps seen only below that width are not bugs.

**A background preview tab draws no frames** (2026-11-16). While the browser pane is hidden, CSS transitions and smooth scrolls stay at `currentTime 0`: `getComputedStyle` reports the start value (a grid column read as `0px`, a `scrollTop` that never moves) and screenshots time out. A screenshot forces a frame. Before calling a layout broken, check `element.getAnimations()`, take a screenshot, or read the value again after one.

**The preview is Vite's dev server, not the production bundle.** Anything that depends on bundling (dynamic imports, CSS chunking, asset URLs, preloads), on native APIs or on WebView2 must also be checked in `npm run build` output or in the installed app.


## The inspector (31 October 2026)

`npm run inspect` opens `/inspector.html`: every screen and state of the frontend, in the real App with fixture data, with look, theme, window size, side by side, and a note on each state that Copy all notes returns as one list.

- **Add a state:** one row in `src/preview/inspector/scenarios.ts`, with `expect` text that proves it appeared. A conversation state is one entry in `src/preview/fixtureScenes.ts` (`?scene=<id>`). A screen is one line in App's `?open=` table. A state only a click reaches uses `steps`, not a new App hook.
- **Check all** opens every state in a hidden frame, runs its steps and looks for its text. Run `window.__inspector.run()` and read `window.__inspector.checks` from a script. A state with no `expect` only proves the page didn't go blank.
- **`&clean`** (added by the index for the main window) turns off first-run hints, the tour and What's New. Mark a scenario `raw` to keep them.
- It runs on the Vite dev server, so it doesn't prove the production bundle or WebView2.
- **Reviewing many screens:** drive the system Chrome headless with Playwright (`chromium.launch({ channel: 'chrome' })`, `reducedMotion: 'reduce'`, URL plus `&no-intro&clean`) and save PNGs. It's far faster than a hidden pane, and it renders what a person would see.

- **Driving it from an agent's hidden browser pane:** transitions and the launch fade crawl, so a column looks too narrow and the shell looks dim. It isn't the app. Inject `*{transition:none!important;animation-duration:1ms!important} .app-shell{opacity:1!important}` before a screenshot.

## Checking the installed app (read-only)

To see what the real window has (attributes, loaded stylesheets, console errors), restart Retinue with the WebView2 debugging port. Restarting stops the daemon and interrupts any bot that is working, so first get the owner's explicit permission at a moment when nothing they care about is running; never restart it as a side effect of another check. Then:

```powershell
Get-Process -Name Retinue | Stop-Process          # the daemon exits with it
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = '--remote-debugging-port=9229 --remote-allow-origins=http://127.0.0.1:9229'
Start-Process "$env:LOCALAPPDATA\Retinue\Retinue.exe"
Invoke-RestMethod http://127.0.0.1:9229/json      # pages: /, ?companion=1, ?dictation=1
```

Then connect to the page's `webSocketDebuggerUrl` with a small Node script (`new WebSocket(...)`, `Runtime.evaluate` with `returnByValue`) and read `document.documentElement.dataset`, `[...document.styleSheets].map(s => s.href)`, `performance.getEntriesByType('resource')`, computed styles, and console/log events. Read only; never print localStorage values that hold tokens. **Afterwards restart Retinue normally without the variable** (the open port lets any local program control the app) and confirm the port is closed.

## UI review checklist

Both supported looks (Retinue and Stone), in dark and light; selected, hover, focus and disabled states; text contrast of 4.5:1 or more; no pill or circle controls in the new looks (the Manager and lock badges and the look orbs excepted); companion and dictation windows if styles changed; reduced motion; the production build when styles or assets load differently.

**Checking `retinue-desktop` from a lane worktree.** It needs three things a worktree lacks: a path with no apostrophe (else `tauri-winres` fails with `RC2135`), `apps/desktop/dist`, and the staged `binaries/retinued-*.exe`. Copy the tree without `target`, `node_modules`, `.git` and `dist` to a short path, run `cargo check -p retinue-desktop` there with `TAURI_CONFIG='{"bundle":{"externalBin":[]},"build":{"frontendDist":"../dist-remote"}}'`, and delete the copy afterwards. The build also rewrites `src-tauri/gen/schemas/*.json`: revert those.

**Flaky under load, besides the known one:** `stopping_a_turn_stops_its_setup_script`. It failed once with five parallel git tests running and passed alone. Mounted UI tests time out if run during cargo builds.

**Check D's free space before starting lanes.** A daemon test build needs about 6 GB. If a lane must build elsewhere, `$env:CARGO_TARGET_DIR` works.

## The performance gate (31 October 2026)

`npm run perf` runs `scripts/perf-gate.mjs`: cold start and `app.snapshot` bytes, lazy and full, on a database seeded by `perf-seed`. Build both binaries first (`cargo build -p retinue-daemon --bin retinued -p retinue-storage --bin perf-seed`). `--self-test` runs the same code with a 1 ms budget and is expected to exit 1. `npm run perf:render` mounts a 1,000-message conversation in happy-dom; it takes about a minute, so it isn't in `npm test`. Budgets live in `perf-budgets.json`, set from measurements. Under load, run `npx vitest run --testTimeout=30000` from `apps/desktop`: mounted tests hit the 5-second limit while Rust compiles, and the root `npm test` swallows the flag.

**Timing the real thing (1 November 2026).** `cargo run --release -p retinue-storage --example snapshot-timing -- <db copy> [--runs 3] [--concurrent 20] [--index] [--plans]` opens a *copy* of the owner's database through `Storage` and reports lazy and full `app.snapshot` (ms and JSON bytes), the per-session context and `turn.error` reads with the plan SQLite chooses, one message-delta write, and how long `settings.get` waits while a snapshot runs. Since the data rework it also reports, as the median of five, the storage work behind changing effort (`agent.update` + `session.model.update`) and assigning a task (`task.create` + `task.dispatch`), each idle, while every conversation is read back to back, and again with `synchronous=NORMAL` (the shipped value stays `FULL`); one conversation opened cold and warm; the same row without its transcript; and a `turnDetailProof` that compares the per-turn `turn.error` lookup with the correlated form it replaced, for every turn. `--index` drops and rebuilds the two `app_events` indexes first and proves every answer is unchanged; `--plans` prints only the query plans of the several shapes of the per-turn lookup (the correlated one is a full scan — see `lessons.md`). It is an example, so `cargo test` never runs it. Copy `%LOCALAPPDATA%\Retinue\retinue.db` **with its `-wal`** into a temp folder, measure there, then delete the copy.

**Coalesced deltas and probe caching (21 November 2026).** The same example now reports `deltaTurn`: one 1,000-chunk turn written the old way (one row update and one event per chunk) and the coalesced way (40 ms / 8 KiB, simulated 2 ms arrivals, real writes), with the commits and event rows it took and the wall time each way. `cargo run -p retinue-runtime --example probe-timing -- [--cache <path>] [--off <provider>]` runs the daemon's own discovery cold, warm and forced and prints `cached`, `probed` and `spawns` (every CLI process the scan started, sign-in included) for each, so "what a relaunch costs" is measurable without starting the app. Give it `--off <provider>` for each provider the owner has switched off, or it probes them as a launch would not.
