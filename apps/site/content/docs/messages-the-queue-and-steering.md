# Messages, the queue and steering

An employee works through one request at a time in each conversation. When it is busy, the messages you send wait in a queue. The queue is shown as rows above the message box, so you can see what is still waiting.

![Messages waiting in the queue](/docs/docs-queue-dark.webp)

## Send a message while the employee works

1. Type your next message in the message box while the employee is still working.
2. Press **Send**. The message joins the queue as a row above the box.
3. Wait for the current turn to finish. The queued message is then sent.

## Send a queued message now

Sometimes a message cannot wait.

1. Find the message in the queue.
2. Choose **Send now**. The employee takes the message into the running turn without waiting for it to finish.
3. If the coding agent cannot take a message in the middle of a turn, the button says **Stop and send** instead. Choosing it stops the current turn, then sends your message. Read the note before you choose it, because the current turn ends.

Claude Code and OpenCode can take a message mid-turn. You can turn this steering on or off in Settings, Coding agents, Providers.

## Good to know

- Long messages stay inside the message box, so you can read them as you edit.
- If a conversation hits a usage limit, the message box says when the limit resets. You can have the conversation resume by itself at that time, or snooze it until you are ready.
- To stop a conversation from asking for your attention for a while, snooze it from the list of conversations.
